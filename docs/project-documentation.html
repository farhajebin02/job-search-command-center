Job Search Command Center

A job search you can talk to · Project documentation

The project

Job hunting is mostly admin. You find a role, you apply, and by week three the spreadsheet is stale and you have lost track of who replied. So I built a job search console you can talk to: say “I applied to the data science role at Kotak” and it is handled.

Approach

I wanted talking to be the whole interface, not a shortcut bolted onto a form. The assistant and the screen work on the same data, so what it does by voice appears on the dashboard straight away. There is no “add application” step to remember, because talking is the step.

I also assumed voice would be messy. People mumble, interrupt, and change their minds mid-sentence, so the design had to be forgiving rather than strict: it acts only on jobs it has looked up, names what it changed, and asks when unsure.

Solution

It runs the search end to end: it reads your résumé, pulls matching roles from Adzuna, and scores each against your background with a match percentage and the specific gaps. It tracks applications through their stages, books interviews on Google Calendar, and runs mock interviews built from the job description and your gaps.

Underneath it is ordinary. A Python API over SQLite holds the résumé, the jobs, the scores, and the pipeline. The browser and the assistant meet in a LiveKit room, where a Gemini Live model listens and answers in speech.

Scheduling shows the priority: an interview is written to the dashboard first and Google Calendar second, so if Google fails you are told plainly.

Mock interviews run as a mode that forgets the earlier conversation, so it behaves like a stranger rather than the friend who spent all afternoon helping you. You can interrupt or leave whenever you like.
