Job Search Command Center

A job search you can talk to · Project documentation

The idea

Job hunting is mostly admin. You find a role, you apply, and by week three the spreadsheet is stale and you have lost track of who replied. I wanted something I could just talk to — say “I applied to the data science role at Kotak” and have it handled — instead of another form to fill in.

So the whole thing is voice-first. You speak, the screen keeps up, and there is no “add application” step to remember, because talking is the step. Everything it does is a real change to real data, so speaking and clicking never disagree.

How it is built

Underneath, it is ordinary. A Python API over SQLite holds your résumé, the jobs it finds, how well each matches you, and where every application stands. The browser and the assistant meet in a LiveKit room, where a Gemini Live model listens and answers in speech. Both sides write to the same database, so nothing needs syncing.

What was actually hard

The hard problems turned out to be human ones. Early on the assistant would tell me it had updated a job when it had quietly changed a different one — guessing at record numbers nobody had given it. Now it can only act on jobs it has actually looked up, and it says which one it touched.

Speech recognition mangles company names constantly, so search had to be forgiving. Say “Senas” and it still finds “Sanas”; when unsure, it asks rather than picking at random.

Mock interviews run as a different mode of the same assistant, not a second one. It forgets the earlier conversation, so it behaves like a real interviewer rather than a friend who has been helping you all afternoon — and you can interrupt it or walk out whenever you want.
