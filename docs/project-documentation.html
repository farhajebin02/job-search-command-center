Job Search Command Center

A job search you can talk to · Project documentation

The project

Job hunting is mostly admin. You find a role, you apply, and by week three the spreadsheet is stale and you have lost track of who replied. So I built a job search console you can talk to — say “I applied to the data science role at Kotak” and it is handled.

Approach

I wanted talking to be the whole interface, not a shortcut bolted onto a form. The assistant and the screen work on the same data, so whatever it does by voice appears on the dashboard straight away, and anything you change by hand, it sees too. There is no “add application” step to remember, because talking is the step.

I also assumed from the start that voice would be messy. People mumble, mishear names, interrupt, and change their minds mid-sentence. The design had to be forgiving rather than strict, and honest when unsure.

Solution

Underneath, it is ordinary. A Python API over SQLite holds your résumé, the jobs it finds, how well each matches, and where every application stands. The browser and the assistant meet in a LiveKit room, where a Gemini Live model listens and answers in speech.

The hard parts were the human ones. Early on the assistant would tell me it had updated a job when it had quietly changed a different one, so now it only acts on jobs it has actually looked up, and names the one it touched. Speech recognition mangles company names, so search is forgiving — say “Senas” and it still finds “Sanas”, and when unsure it asks instead of guessing.

Mock interviews run as a mode that forgets the earlier conversation, so it behaves like a stranger rather than a friend who has been helping you all afternoon — and you can interrupt it or leave whenever you like.
